# QBUY ADM 工作總覽／訂單管理第一輪修改紀錄

日期：2026-11-01（Asia/Taipei）

## 目標與範圍

初期一人管理，但營運資訊與操作文字需供未參與開發的授權人員理解；手機、桌面均應可操作。

本輪調整：
- 工作總覽從舊 `Order` 改以 QB `Checkout`、`QbOrder` 與營運佇列為主，標示計數單位及工作原因。
- 訂單管理 `/admin/qbuy` 增加「購買紀錄／正式訂單」兩個入口，明確區分付款前後狀態。
- 保留原有人工核帳、退款、取消、物流表單與後端服務；不重新計算或改寫交易資料。
- 提供 `/admin/preview/orders` 開發專用模擬測試頁，28 筆購買與 16 筆正式訂單的多情境卡片；與真實交易視圖共用元件。
- ADM 手機導覽改為抽屜，支援 Esc、背景捲動鎖定、基本焦點循環。
- 付款確認新增按狀態查詢入口，方便工作總覽直達待核帳、異常及待建單紀錄。
- 已定稿的消費者端與舊制訂單資料表、服務、路由不變。

## 重要資料定義

- 購買紀錄：Checkout，可存在於未付款／未建單階段。
- 正式 QB 訂單：QbOrder，只有正式建單後才存在。
- 物流：FulfillmentGroup，可能一個 Checkout 中有多個配送群組。
- 工作總覽的「等待建立物流」為符合既有 QB 工作佇列的 Checkout 數量，不是運送包裹數或已可立即執行的操作數。
- 各待辦佇列可能重疊，不可相加作待辦總數。
- 轉帳回報不是銀行實際收款；退款義務不是已退款。

## 模擬測試資料的限制

預覽頁：
- 僅在非 Production 且完成管理員認證後可存取。
- 使用靜態合成情境，沒有任何正式或測試資料庫寫入。
- 不會真的觸發收款、取消、退款或物流，也不能取代端到端交易測試。
- 正式 QB 工作台仍會從既有資料庫顯示真實紀錄。

下一輪如要驗證交易操作，需使用 `scripts/lib/e2e-database.ts` 既有隔離資料庫機制建立有效 Checkout、QbOrder 與相關關聯，並在瀏覽器跑完整 E2E。
